# Architectural Contracts

Stated contracts for the KMiDi platform. Each item declares the *what*, *who*, and *invariant* — the precise behavior the system commits to. These are conceptual contracts that override implementation details; if code disagrees with a contract, the code is wrong (and conversely, contract changes require updating the dependent code paths).

Companion docs:
- `AGENTS.md` — runtime / build / FFI map (implementation truth)
- `docs/NATIVE_SAFETY_AND_FFI.md` — native safety enforcement (RT, FFI ownership, JUCE/ODR)
- `docs/audit/RT_CALLBACK_AUDIT_2026-05-22.md` — verified-present infrastructure + RT audit
- `shared_schemas/` — canonical schema sources (auto-synced to TS/Rust/Python)

## 1. Clear system boundaries

**Contract.** KMiDi has exactly three runtime tiers and one build tier:

| Tier | Role | Boundary surface |
|------|------|------------------|
| Frontend (React + Vite, `src/`) | UI, intent authoring, emotion wheel | HTTP to Music Brain API; latent `@tauri-apps/api` shim (no host present in canonical tree — see `vite.config.ts`'s `tauriStubPlugin`) |
| Music Brain API (Python FastAPI, `music_brain/`) | Generation, intent normalization, orchestration | HTTP `/generate`, `/docs`; consumes intent schema; produces `GeneratedMidi`/audio artifacts |
| Native engine (KellyFFI dylib, `src/`, `engine/`, `src_penta-core/`) | DSP, plugin host, RT-safe inference glue | KellyFFI combined C ABI (`kelly_*` C++ half + `IntentFrameBuilder_*`/`validate_intent_frame_ffi` Rust half from embedded `intent_ir` staticlib) |
| Build (CMake + npm + uv + cargo) | Reproducible artifact generation | Lock files: `package-lock.json`, `Cargo.lock`, `uv.lock`; `external/JUCE/` submodule pinned to JUCE 8 |

No fourth tier (no Tauri desktop shell in the canonical tree).

## 2. Unified state model

**Contract.** Single source of truth for intent / emotion / IntentFrame is `shared_schemas/`. Generated targets are derived, never authored. Drift across the 9 generated artifacts (3 JSON schemas + 3 TS types + 3 Rust generated types) is rejected by `.github/workflows/ci.yml`'s drift guard. Re-running `python3 scripts/sync_entities.py` must produce zero diff against the committed tree.

## 3. Canonical event pipeline

**Contract.** Generation events flow in exactly one direction at each tier boundary:

```
UI intent  →  /generate (HTTP)  →  IntentResult / EmotionalIntent
                                ↓
                       music_brain generation
                                ↓
                       GeneratedMidi (vectors of NoteEvent/ChordEvent)
                                ↓
       message-thread write to inactive midi buffer slot
       (`midiBuffers_[shadow] = midiGenerator_.generate(...)`)
                                ↓
       atomic release-store of `activeMidiBuffer_`
                                ↓
       audio thread acquire-load + schedule via `midiMessages.addEvent`
```

The atomic shadow-swap RCU pattern is the canonical hand-off between message and audio threads. No path bypasses it.

## 4. Stable plugin ABI

**Contract.** KellyFFI dylib exposes one combined C ABI with two halves:

- **`kelly_*` (C++)** — declared in `src/bridge/kelly_ffi.h`, implemented in `src/bridge/kelly_ffi.cpp`. CMake target carries `VERSION 1.0.0 SOVERSION 1`.
- **`IntentFrameBuilder_*` / `validate_intent_frame_ffi` (Rust)** — declared in `engine/intent_ir/src/ffi.rs`, header generated by `engine/intent_ir/cbindgen.toml`.

Breaking either half = SOVERSION bump + coordinated update of all C++/Python/test consumers. Strings allocated by the library are freed by the library (`kelly_free_string`); strings with static storage are documented as such and never freed by callers.

## 5. Stable IPC schemas

**Contract.** All inter-tier message types are defined in `shared_schemas/` and synced to language-specific bindings by `scripts/sync_entities.py`. The schemas are: `CompleteSongIntentRequest.json`, `emotion_schema.json`, `intent_frame_schema.json`. The `/generate` HTTP API uses `GenerateRequest`/`EmotionalIntent` (defined inline in `music_brain/api.py`) which is a thinner request-time contract; engine-internal contracts use the full `CompleteSongIntentRequest`.

## 6. Clear rollback semantics

**Contract.** Rollback operates at the command-pattern layer (`music_brain/agents/command.py`). Every state-changing operation in `UnifiedHub` is a Command with `do()`/`undo()`. The audio thread itself does not roll back — it consumes the active MIDI buffer slot; rollback occurs in the generator path before the next atomic shadow-swap. Audio is never "rewound mid-block."

## 7. Clear orchestration ownership

**Contract.** Multi-instrument orchestration is owned by `music_brain/orchestrator/orchestrator.py`. Track-level orchestration decisions (`music_brain/kelly_companion/engines/orchestration.py`) are subordinate. Training orchestration (`music_brain/penta_core/ml/m4_training_orchestrator.py`) is a peer concern, not nested under generation orchestration.

## 8. Clear synchronization

**Contract.** Three primitive families exist; no others may be introduced on the audio thread:

| Primitive | Use | Location |
|-----------|-----|----------|
| `std::atomic` with documented memory order | Audio-thread state publication | `include/penta/common/RTState.h` |
| Seqlock (`begin_publish`/`end_publish`/`rt_state_snapshot`) | Multi-field atomic publication | Same |
| SPSC ring buffer (`readerwriterqueue` / `concurrentqueue`) + `std::binary_semaphore` wake | Audio→worker handoff | `src/ml/InferenceThreadManager.h` |

Message-thread code may use `std::mutex` / `std::lock_guard` (`intentMutex_`). Audio thread may not.

## 9. Clear generation authority

**Contract.** Generation is initiated by the user (UI intent submit) or by automation (e.g., AI suggestion accept). The Music Brain API computes a candidate `GeneratedMidi`. The native engine's audio thread is a consumer only — it never decides *what* to generate, only *when* to play. The host DAW transport is the authoritative clock; the engine reads `playHead->getPosition()` and never asserts its own time.

## 10. Clear CPU / GPU ownership

**Contract.** CPU owns: the audio callback, RT-safe inference glue (InferenceThreadManager worker thread), DSP graph, intent normalization. GPU/ANE owns: heavy ML inference (Audio JEPA, Chord JEPA, emotion runner) via CoreML / ONNX / RTNeural backends. The audio thread never directly calls GPU APIs; it reads ML results through the lock-free SPSC ring buffer.

## 11. Clear DSP lifecycle

**Contract.**

1. `prepareToPlay(sampleRate, samplesPerBlock)` — allocate all buffers (lookahead, monoMix, EQ state, latency manager). Configure feature extractor, ML lookahead. Cache APVTS pointers.
2. `processBlock(audio, midi)` — `noexcept`. No heap allocation, no locks, no blocking IO. Consumes preallocated buffers and ML inference results.
3. `releaseResources()` — release host-owned resources. May allocate.

Any DSP module added to the chain must implement this three-phase lifecycle.

## 12. Clear export determinism

**Contract.** Offline render (`/generate` with deterministic seed) and online inference are distinct entry points. Offline export must produce byte-identical output for identical (intent, model checkpoint, seed). Online inference is permitted to differ run-to-run due to wall-clock timing of streaming chunks. The export pipeline is responsible for fixing all sources of nondeterminism (seed seeding, thread scheduling, GPU kernel ordering) before computing the output.

## 13. Clear telemetry boundaries

**Contract.** Telemetry surfaces:

| Layer | Sink | Purpose |
|-------|------|---------|
| Audio thread | `latencyInstrument_.measure()` per block; `callback_stats.json` via `rt_harness` | RT-safe latency P50/P90/P99 |
| C++ core | `src/core/logging.cpp` | Non-RT log routing |
| Python | `music_brain/orchestrator/logging_utils.py`, `music_brain/agents/telemetry.py` | Generation/orchestration tracing |

Audio thread emits *only* through `latencyInstrument_`. No `printf`, no logger calls, no syscalls on the callback.

## 14. Clear phrase continuity

**Contract.** Phrase boundaries are predicted by `music_brain/structure/sections.py` + `progression.py`. The arrangement engine (`src/engines/ArrangementEngine.cpp`) preserves phrase identity across regeneration: a regeneration request scoped to a single phrase must not invalidate adjacent phrase state. Motif persistence is tracked in the intent contract; the audio thread is unaware of phrase boundaries (it processes whatever MIDI is in the active slot).

## 15. Clear AI authority boundaries

**Contract.** AI is advisory. The user owns:
- The intent (emotional, technical, structural)
- Final acceptance of generated content
- All edits to the arrangement timeline

AI provides:
- Generated MIDI / chord progressions / arrangements
- Confidence scores on suggestions
- Latent-space proposals for steering

The DAW host owns the transport clock; the AI never asserts BPM, time signature, or playhead position.

## 16. Clear planning vs realization distinction

**Contract.** Planning (`music_brain/structure/`, `music_brain/penta_core/ml/`) produces symbolic intent (notes, chords, sections, dynamics). Realization (`src/plugin/PluginProcessor.cpp::processBlock`) converts symbolic intent to audio samples + MIDI events at host-driven sample positions. These are separated by the GeneratedMidi contract — no code path collapses planning and realization into a single function.

## 17a. Plugin format coverage (decided)

**Contract.** v1 ships **VST3 + AU + CLAP** for plugin host support. This covers Logic, Ableton, Reaper, FL Studio, Cubase, Bitwig, Studio One, Cakewalk, and GarageBand — effectively the entire creator/indie DAW market.

**AAX is explicitly deferred.** It is the only plugin format Avid Pro Tools requires, and distribution additionally mandates PACE iLok wrapping (proprietary copy-protection middleware with high CI/CD friction and vendor lock-in). AAX is a "court Pro Tools studios" decision appropriate for vN once product-market fit is established. It is **not** a v1 gap.

## 17. Clear deterministic vs probabilistic systems

**Contract.** Deterministic subsystems (must produce identical output for identical input):

- Schema validation, intent normalization
- DSP graph (signal processing on a known buffer)
- Atomic publishing protocols (seqlock, RCU shadow-swap)
- Offline export pipeline (with seeded RNG)
- C ABI surface (return values, ownership)

Probabilistic subsystems (run-to-run variation is acceptable):

- ML inference (sampling, top-k/top-p decoding)
- Online streaming inference (latency-sensitive, may drop)
- Constraint-based decoding with stochastic relaxation
- Emotion runner (model nondeterminism with documented seed)

The boundary between the two is the GeneratedMidi contract: probabilistic systems write into it; deterministic systems read from it. Once written, the contents are byte-fixed until the next atomic swap.

## Status

- Items 1–4, 8, 11 are **enforced by code** (CI drift guard, atomic patterns in `RTState.h`, RT-callback audit findings, FFI link discipline in CMake).
- Items 5, 7, 13–14 are **enforced by file layout** (single ownership of the named modules).
- Items 6, 9–10, 12, 15–17 are **policy contracts** — followed by current code but not actively asserted by tooling; future tooling work (e.g., RTSan, export hash regression test) would graduate them to enforced.
